## My very scientific development process

I like software that makes technology feel personal. Custom experiences, clever integrations, tiny quality-of-life upgrades — stuff that solves a problem without making you fight the interface.

My extremely scientific process is usually something like this:

<div align="center">

<img src="https://readme-typing-svg.demolab.com?font=Share+Tech+Mono&amp;weight=700&amp;size=17&amp;duration=1500&amp;pause=350&amp;color=00F0FF&amp;center=true&amp;vCenter=true&amp;width=760&amp;height=45&amp;lines=FIND+A+PROBLEM;BUILD+A+PROTOTYPE;BREAK+SOMETHING;DEBUG+THE+HELL+OUT+OF+IT;SHIP+THE+FIX;REPEAT" alt="Animated development loop"/>

</div>

- Get an idea and start building immediately.
- Hit a weird error. Google the error.
- Somehow make it worse.
- Finally fix it and pretend that was the plan.
- Commit before touching anything else.

## A few things about how I build

<table>
<tr>
<td width="50%" valign="top">

### Stuff I care about

- Apps should feel good to use, not just look good in screenshots.
- If I'm going to use something every day, I want to customise it.
- I like figuring out how things work under the hood.
- A small useful tool beats a giant app full of buttons nobody needs.

</td>
<td width="50%" valign="top">

### Stuff that happens anyway

- "I'll just fix this one thing."
- Three unrelated bugs appear.
- Somehow the UI looks worse now.
- Revert half the changes.
- It works. Don't touch it. Make a backup.

</td>
</tr>
</table>
